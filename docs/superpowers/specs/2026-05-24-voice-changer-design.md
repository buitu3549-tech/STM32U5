# 实时变声器 — 设计规格书

**日期:** 2026-05-24  
**目标:** Windows 桌面实时变声器，3 个角色音色预设，低延迟神经网络方案

---

## 1. 产品概述

### 1.1 核心功能
- 实时采集麦克风音频，经过神经网络音色转换后输出到虚拟扬声器
- 3 个角色预设：甜妹音、御姐音、温青音
- 极简悬浮窗 UI，游戏内友好

### 1.2 目标用户
- 游戏玩家（语音开黑时改变声音）
- 语音聊天用户

### 1.3 非功能需求
- 端到端延迟 < 50ms（目标 < 30ms）
- CPU 占用 < 20%（单核）
- 模型切换 < 2 秒
- 常驻内存 < 300MB

---

## 2. 技术栈

| 层 | 技术 | 理由 |
|----|------|------|
| GUI | Qt 6 + QML | 原生悬浮窗、系统托盘、跨平台潜力 |
| 音频采集 | PortAudio + WASAPI | 低延迟 Windows 音频 |
| 特征提取 | WORLD 声码器 | 轻量 F0 + 频谱包络提取 |
| 推理引擎 | ONNX Runtime (CPU) | C++ 原生、无 GPU 依赖 |
| 音色模型 | RVC → ONNX (3 个独立模型) | 预训练社区模型先跑通 |
| 声码器 | HiFi-GAN → ONNX (共享) | 特征 → 波形 |
| 虚拟设备 | VB-Audio Virtual Cable | 音频劫持到游戏 |
| 构建 | CMake + MSVC 2022 | Windows 标准工具链 |

## 4. 音频管线

### 4.1 参数
- 采样率: 48kHz
- 帧大小: 256 样本 (5.3ms/帧)
- 位深: 16-bit PCM
- 声道: 单声道

### 4.2 处理流程与时间预算

| 阶段 | 操作 | 目标延迟 |
|------|------|----------|
| 1 | WASAPI 独占模式采集 | ~5ms |
| 2 | 预加重 + WORLD 特征提取 | ~8ms |
| 3 | ONNX 音色转换推理 | ~10ms |
| 4 | HiFi-GAN 声码器 | ~5ms |
| 5 | 后处理 + WASAPI 输出 | ~2ms |
| **总计** | | **~30ms** |

### 4.3 优化策略
- 模型 FP16 量化，体积减半推理加速 30%
- WASAPI 独占模式旁路系统音频栈
- ONNX 线程绑定高性能 CPU 核
- 双缓冲流水线，采集和推理并行

## 6. 模型策略

### 6.1 阶段一：开源模型
- 从 RVC 社区下载 3 个对应音色的 .pth 模型
- 转换为 ONNX 格式 (FP16)
- 共享一个 HiFi-GAN 声码器 ONNX

### 6.2 阶段二：自训练（后续）
- 收集目标音色干声数据（每个角色 10-30 分钟）
- 用 RVC 训练脚本微调
- 替换 ONNX 模型

### 6.3 模型加载
- 启动时加载默认角色模型
- 切换角色时后台加载新模型（<2s），加载完无缝切换
- 加载期间旧模型继续服务，不中断音频流

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 开源模型音色不匹配 | 效果不如预期 | 预留自训练流程，快速迭代 |
| 延迟超标 | 用户体验差 | 帧大小可降至128，模型可进一步剪枝 |
| 虚拟音频驱动兼容性 | 部分机器装不上 | 提供备选方案（WASAPI 回环） |
| ONNX 算子不兼容 | 模型加载失败 | 限定 ONNX opset，预验证转换结果 |
